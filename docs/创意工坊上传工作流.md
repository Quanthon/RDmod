# 创意工坊上传工作流

## 日常入口

仓库根目录双击：

| 入口 | 行为 |
| --- | --- |
| `编辑工坊资料.bat` | 打开 `workshop/`，修改标题、介绍、更新说明、封面等 |
| `准备工坊上传.bat` | 校验资料、重新构建 Release、打包并准备上传目录；不连接 Steam |
| `上传创意工坊.bat` | 构建 → 发布 GitHub 源码与安装包 → 生成图片直链 → 上传工坊 |
| `发布GitHub.bat` | 只发布 GitHub 源码、素材和 Release，不上传工坊 |
| `登录GitHub.bat` | 首次使用时登录 Quanthon 的 GitHub 账号 |
| `打开工坊页面.bat` | 根据保存的工坊 ID 打开页面 |

上传前先用 `登录GitHub.bat` 登录 Quanthon，并启动、登录 Steam。当前版本号读取 `Mod/RDmod.json`，默认不会再次询问或递增版本。需要推进版本时先用 `打包发布.bat` 设置版本，或者修改清单中的 version；工坊入口始终重新构建，不复用旧 ZIP。

首次上传默认 `private`（私密）。准备公开时，在 `workshop/workshop.json` 把 visibility 改为 `public`，再双击上传；若以后只想在网页管理可见性，设为 null 或删除该字段，避免下一次上传改回私密。

## 可编辑资料

| 文件 | 用途 |
| --- | --- |
| `workshop/workshop.json` | title 标题、visibility 可见性、tags 标签、dependencies 依赖 ID、contentDescriptors 内容描述符 |
| `workshop/description.txt` | 工坊详细介绍；支持多行文本及 Steam BBCode，不需要手写 JSON 换行 |
| `workshop/changelog.txt` | 本次更新说明，上传前按版本修改 |
| `workshop/image.png` | 工坊封面，替换为小于 1 MB 的有效 PNG；初始复用项目角色选择背景 |
| `workshop/settings.json` | 上传器路径、介绍及更新说明文件路径；相对路径以 workshop 文件夹为基准 |

所有文本使用 UTF-8。已填入中英文介绍和 RitsuLib 工坊依赖 ID `3747602295`，可以直接修改。PNG 封面独立复制，不会修改项目素材。

可见性支持 private、public、unlisted、friends_only。
填写的资料会在每次上传时同步至工坊。标题、标签等字段设为 null 或删除可保留网页上的设置。若要由网页管理介绍，先将 settings.json 的 description_file 设为 null，再将 workshop.json 的 description 设为 null 或删除。change_note_file 同理。

dependencies 明确维护完整数字 ID 列表，始终保留 RitsuLib。官方上传器 v0.2.0 会将省略的依赖按空列表处理，因此此入口会阻止缺少 RitsuLib 的配置。无需把 RitsuLib 的文件打入本 Mod。

## 发布流程与文件

Python 实现统一位于 `Scripts/upload_workshop.py`，BAT 只定位目录、调用 Python 和暂停。
上传流程：资料和封面校验 → 本地化静态检查 → 调用 `package_local_release.py` 重新生成当前版本 ZIP → 核对 SHA256、CRC、清单与三文件范围 → 发布 GitHub 源码和 Release、验证图片直链 → 准备 `workshop/.upload/` → 调用官方上传器。GitHub 任一步失败会停止，不继续上传工坊。`--prepare` 仅生成本地预览，不发布 GitHub。

上传的 content 只含 RDmod.dll、RDmod.pck、RDmod.json。可编辑资料保留在 workshop 根目录，`.upload` 为自动生成目录，不直接编辑。

构建或校验失败时不会调用上传器。上传失败保留资料、ID 和日志；已成功构建的本地 ZIP 仍可使用。Steam 条款或可见性审核由工坊页面提示处理。

首次上传成功后保存 `workshop/mod_id.txt`，并另存 `mod_id.backup.txt`。后续上传使用同一 ID；主文件缺失时会从备份恢复。请备份这两份文件，它们不会提交到 Git。已经有工坊页面时，把网址中的数字 ID 写入 mod_id.txt；迁移电脑时一起复制此文件。

官方上传器可能在创建条目后才遇到提交失败。此入口会从实际上传日志捕获条目 ID，保留下次重试；如果首次上传中断且还未取得 ID，会留下 upload-pending.txt 并阻止盲目创建第二个条目。此时查看日志与自己发布的工坊项目，恢复 ID 后重试；只有确认没有创建条目时才删除该标记。

日志：`workshop/logs/<时间>-upload.log`，另有上传器目录下的 mod-uploader.log。若异常强制关闭窗口留下 `.workflow.lock`，先确认没有上传或构建进程运行，再删除该锁文件。

## 命令行

```powershell
# 只校验配置，不构建、不上传
python Scripts/upload_workshop.py
# 重新构建和准备文件，不上传
python Scripts/upload_workshop.py --prepare
# 重新构建并直接上传
python Scripts/upload_workshop.py --upload
# 打开资料或工坊页面
python Scripts/upload_workshop.py --edit
python Scripts/upload_workshop.py --open-page
```

## GitHub 公开源码、素材与安装包

目标公开仓库：`Quanthon/RDmod`。首次发布会创建不存在的仓库；已有私有仓库不会自动改成公开。
由 Quanthon 编写的代码采用 MIT，图片、音频和角色形象见 ASSET_NOTICE.md。

公开当前源码快照，而非本地 Git 历史。明确收录 Mod 的源码与运行素材、Python 发布/开发工具、必要说明、工坊资料及描述引用的图片。
不包含 .godot、.vscode、工具二进制、官方反编译参考、设计工作簿、日志、凭据与工坊 ID。
运行 `python Scripts/upload_workshop.py` 可在 `workshop/github-preview.json` 查看完整公开清单。

源码推送到仓库默认分支；公开快照保存在 `.tools/github-publish/`。不要手工在此临时目录开发。
远程分支有分叉时停止，避免强推。上次公开后删除的源码会报告并停止，需要先确认远程处理；不会静默删除文件或把旧代码当作最新发布。

每次发布上传 `dist/RainbowDash-版本.zip` 及 SHA256 到 GitHub Release `v版本`。
相同版本重传会替换同名安装包；源码发生玩家可见变化时应先推进 Mod 版本，以便清楚区分发行版本。
下载者从 Releases 拿到可直接安装的 DLL/PCK/JSON；GitHub Source code ZIP 则用于开发。
RitsuLib 仍需单独安装。GitHub 发布成功不代表工坊已上传；工坊失败时 GitHub 成果保留，可再次运行上传入口。

## 描述图片与 GIF

1. 将图片放在 `workshop/media/`，支持 PNG、JPG、GIF、WebP，单文件小于20MB。
2. 在 description.txt 中插入：

```text
[img]media/character.png[/img]
[img]media/战斗演示.gif[/img]
```

实际发布先上传被描述引用的本地图片，再用本次提交 SHA 生成 GitHub Raw 地址，并匿名下载校验图片。
只有校验通过后才继续工坊上传。中文文件名自动编码。原 description.txt 保留可编辑的本地引用；最终描述见 `.upload/workshop.json`。
`--prepare` 显示默认 main 分支格式的预览地址，不代表图片已公开；实际上传始终使用已推送的提交 SHA。
已有完整 HTTPS 图片地址保持原样；未被描述引用的 media 文件不自动公开。

## GitHub 登录与配置

`workshop/settings.json` 的 github.repository 为公开目标，github.cli 为 GitHub CLI 路径。
本机安装官方 GitHub CLI 2.100.0 于 `.tools/gh-2.100.0/bin/gh.exe`。
下载来源：https://github.com/cli/cli/releases/tag/v2.100.0
Windows x64 ZIP SHA256：227e35230b25db3fa1b997bab7cf4d67df0470a3b75b99e4ee66bce1a7cd4e72。

双击 `登录GitHub.bat`，按终端提示在浏览器完成授权。凭据由 GitHub CLI 管理，不写入项目文件。
发布前检查登录账号为 Quanthon；账号不符或未登录会停止。当前实现创建个人账号仓库，组织仓库请先在网页建立并配置有权限的账号后调整流程。

命令行：

```powershell
python Scripts/upload_workshop.py --login-github
python Scripts/upload_workshop.py --github-only
```

开发测试：`python -m unittest discover -s Scripts/tests -p test_publish_github.py`。
